# 个人版 T3 维护约定

本文记录用户对本仓库的长期维护要求，供后续 agent 接手时读取。用户在当前任务中的明确指令优先；不要将一次部署授权扩展成以后任务的默认行为。

## 日常开发的默认范围

- 全程用中文汇报调查结果、进度和交付状态。
- 收到新特性或缺陷请求时，默认完成代码调查、编辑和必要测试；不构建发布版本，不安装、不替换、不重启运行中的 T3。
- 只有用户明确要求时，才构建版本或部署。按指令指定的设备操作：只要求安装到 MacBook，不代表同时更新 LTR-DEV；仅要求构建产物，也不代表授权安装。
- 已明确授权的步骤直接完成，不为同一范围重复索取确认。缺少必要信息或发现活跃会话等实际阻碍时，说明具体原因。
- 未经明确要求，不创建 PR。
- 界面修改尽量沿用 T3 原生组件和排版规范，优先复用已有设置行；保持文字、控件、间距、圆角半径和垂直对齐一致。余额使用紧凑可换行卡片和已有厂商图标；默认不展示来源设备或上报时间。策略命名使用对称的 Hardware / Usage，避免另造一套视觉风格。

## 运行实例与维护窗口

用户会持续通过 T3 会话维护 T3 本身。修改源码与替换正在承载会话的程序是不同操作，不能把测试或依赖安装顺带变成生产更新。

执行已授权的安装或重启前：

1. 核对目标设备、实际应用路径、服务启动方式及当前运行版本，不只检查某个源码检出的 HEAD。
2. 检查目标服务端有无运行、排队、准备中或等待交互的任务；等待用户输入的 agent 也不应当被当作空闲。
3. 有活跃任务时，先准备可审阅的产物，再安排维护窗口；不要为了安装而中断任务。无活跃任务且本次已获安装、重启授权时，继续执行。
4. 保留旧应用和数据备份，准备可恢复的旧版本。Mac 安装必须采用 [有保留上限的压缩回滚流程](personal-desktop.md#personal-macos-installation-and-rollback-retention)：默认保留 1 份、最多 2 份；不重复复制旧应用、不备份整份 T3 home、不长期保留解压的 `.app` 暂存副本，完成后校验 Spotlight 只命中正式应用。遵守根目录 `AGENTS.md` 对线上数据的保护要求，测试使用隔离副本。
5. 检查桌面内置后端与独立后台服务是否争用同一 T3 home 或端口。不能删除占用锁绕过检查，也不能按进程名称批量终止服务。
6. 安装后核对实际运行版本、后端就绪状态、设备标识和会话数据完整性。启动成功不等于功能验收已经完成。

运行版本、构建目录、发布分支及备份位置以现场核对为准。发布检出可能包含尚未合回日常开发分支的独立修复；下一次构建前比较发布源码与开发源码，避免覆盖已部署的修复。

## 交付状态必须分开说明

| 状态       | 需要说明的事实                                           |
| ---------- | -------------------------------------------------------- |
| 源码修复   | 所在分支、提交及已完成的检查；与独立工作区修复的整合关系 |
| 构建产物   | 目标平台、架构、版本、产物位置及校验结果                 |
| 安装       | 实际替换了哪台设备、哪个应用或服务，是否重启，备份在哪里 |
| 运行时验收 | 实际执行了哪些检查，哪些场景仍未验证                     |

不要将未执行的阶段写成已完成。单元测试、浏览器夹具测试、真实数据快照回放和生产请求测量是不同证据。例如，Forgejo PR 快照回放不能证明生产 `vcs.refreshStatus` 的实际延迟；远程机器链接失败也不能抹去另一路径已完成的安装与启动核验。

## 已确认的产品语义

- **设备调用拓扑**：LTR-DEV、lenovo-px、prod-dev-fpga、LTR-personal、MacBook 五台桌面设备应能通过 T3 两两调用，并均能调用 lab-edge-01；lab-edge-01 仅作为调用目标，不配置调用其他设备的出站 Link。区分桌面客户端保存的 environment 与服务端 agent 的后台 Link，分别验证。
- **设备**指实际承载 agent/session 的 T3 服务端设备（environment），不是打开客户端的设备。按 session 所属服务端筛选，并支持同一设备内跨 project 查看、运行中数量和连接状态。
- **自动分派的模型范围**应是符合条件设备上的模型并集。只有一台设备支持某个模型时，该模型仍可选，任务只能分派到支持所选 provider 和模型的设备。
- **订阅 Usage 分派**仅基于目的地已确认的订阅账号，安装 CLI 不等于拥有订阅；API 余额不参与。对支持同一模型的账号，以识别出的套餐月价乘剩余额度比例排序，不要求厂商披露绝对额度，也不要求用户手填倍率。这是用户指定的近似策略：$200 套餐按 $20 套餐的 10 倍权重计算，剩余 5% 与后者剩余 50% 同分；不是厂商真实额度的保证。无法识别价格时不猜测。
- **API 余额**由 key 所在设备通过厂商接口查询，不暴露 key 本身；同一个 key 在多设备、多份 OpenCode 配置中使用时，只展示一份余额。厂商接口支持程度和去重策略应区分已验证事实与推测，不把讨论中的候选方案写成既定要求。

## 工具与连接注意事项

使用仓库固定的 Node 和 Vite+ 工具链，尤其是检查和 Git 提交钩子；系统 Node 可能不支持仓库的 TypeScript 工具脚本。个人版构建方法见 [Personal desktop development](personal-desktop.md)。

跨设备访问不能把目标机器的 `127.0.0.1` 当成远程可达地址。T3 机器链接、SSH 通道和应用安装的结果分别核验；一种连接失败，不代表其他路径也失败。

本文只维护长期约定，不保存逐次发布日志、临时计划、令牌、API key 或配对链接。具体任务和部署证据保留在相应的外部报告中。
